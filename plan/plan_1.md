## 二、核心组件职责表

| 组件 | 部署位置 | 核心职责 | 存储内容 |
| :--- | :--- | :--- | :--- |
| **你的电脑 (Client)** | 你家 | 写代码、push、看Web、下载模型 | 本地代码 + 下载的模型文件 |
| **GitHub** | 公网 SaaS | 代码版本管理、触发训练 | 训练脚本 (文本) |
| **云服务器 (Task Server)** | 公网云 (2C2G) | 任务调度、API网关、Web展示 | SQLite (任务状态/指标) + 本地磁盘 (最终模型/日志归档) |
| **Agent** | 公司训练机 | 拉任务、跑训练、上报状态 | 无持久化 (只缓存代码) |
| **训练子进程 (train.py)** | 公司训练机 | 执行RL训练 | **所有中间 Checkpoint 存本地** |
| **代理服务器** | 公司内网 | 让内网机器访问外网 | 不存储 |

## 三、完整数据流 (一次任务的完整生命周期)

### Phase 1: 提交任务 (你在家)
1. 你修改 `train.py`，执行 `git add . && git commit -m "new reward" && git push`。
2. GitHub 自动发送 Webhook 到 `http://云服务器IP:8000/webhook/github`。
3. 云服务器收到通知，在 SQLite 创建一条记录：
   ```sql
   INSERT INTO jobs (id, status, commit_sha, repo_url, create_time)
   VALUES ('123', 'PENDING', 'abc123', 'git@github.com:...', now());
   ```

### Phase 2: Agent 拉取任务 (公司训练机自动)
4. Agent 每 30 秒轮询云服务器：`GET /jobs/pending`。
5. 发现 Job 123，立即用**乐观锁**抢占 (原子更新 `status='ASSIGNED'`)。
6. Agent 执行：
   ```bash
   git clone git@github.com:... /workspace/job_123
   cd /workspace/job_123 && git checkout abc123
   pip install -e .
   ```

### Phase 3: 执行训练与实时上报 (训练中)
7. Agent 启动子进程：`nohup python train.py --job-id 123 > train.log 2>&1 &`。
8. 训练脚本每 100 步把 Loss 写入本地 `metrics.jsonl`。
9. **Agent 并行做三件事**：
   - 每 5 秒 `tail -n 50 train.log` 新增行 -> `POST /jobs/123/logs`。
   - 每 10 秒读取 `metrics.jsonl` 最新行 -> `POST /jobs/123/metrics`。
   - 每 30 秒执行 `nvidia-smi` -> `POST /jobs/123/heartbeat` (带 GPU 利用率)。
10. 云服务器收到数据后写入 SQLite (指标) 和内存缓存 (日志最近 5000 行)。

### Phase 4: 保存模型 (两种策略)
11. **中间 Checkpoint (留公司)**：训练脚本每 1000 步保存 `model_1000.pt` 到公司本地 `/data/checkpoints/123/`。Agent 不处理，纯本地保存。
12. **最终模型 (传云端)**：训练结束，Agent 找出 best_model.pt，通过 `POST /jobs/123/checkpoint` 上传到云服务器的 `/data/gradmotion/123/best_model.pt`。

### Phase 5: 你在家观测与下载
13. 打开浏览器访问 `http://云服务器IP:8000/dashboard/123`，看到实时更新的 Loss 曲线。
14. 执行 `curl http://云服务器IP:8000/jobs/123/logs` 看最新日志。
15. 训练结束后，点击网页上的“下载最终模型”，或执行 `wget http://云服务器IP:8000/jobs/123/checkpoint/best_model.pt`，直接存到你桌面。

## 四、存储策略 (关键：什么存哪里)

| 数据类型 | 存储位置 | 保留策略 | 用途 |
| :--- | :--- | :--- | :--- |
| **训练代码** | GitHub | 永久 | 版本管理、可追溯 |
| **任务元数据 (status, create_time)** | 云服务器 SQLite | 永久 | 任务管理 |
| **Loss / Reward 指标** | 云服务器 SQLite | **仅保留最近 7 天** (定时清理) | 画实时曲线 |
| **实时日志 (最近 5000 行)** | 云服务器 内存缓存 | 内存中，重启丢失 | `tail -f` 效果 |
| **完整日志归档** | 云服务器 本地磁盘 | 永久 | 查错备用 |
| **中间 Checkpoint (model_*.pt)** | **公司训练机 本地硬盘** | 永久 | 断点续训 |
| **最终模型 (best_model.pt)** | 云服务器 本地磁盘 | 永久 | 供你下载 |

## 五、网络连接矩阵 (谁连谁，怎么连)

| 源 | 目标 | 协议 | 是否可行 | 依赖 |
| :--- | :--- | :--- | :--- | :--- |
| 你家电脑 | 云服务器 (公网IP) | HTTP/HTTPS | ✅ 直连 | 无 |
| 你家电脑 | 公司训练机 (10.12.201.5) | SSH | ❌ 不可达 | 内网IP，你家无法访问 |
| 公司训练机 | 云服务器 (公网IP) | HTTP/HTTPS | ✅ 通过代理 | `http_proxy=10.12.201.122:39000` |
| 公司训练机 | GitHub | git/HTTPS | ✅ 通过代理 | Git 配置 `http.proxy` |
| GitHub | 云服务器 (公网IP) | Webhook (HTTP) | ✅ 直连 | GitHub 设置 Webhook URL |
| 你家电脑 | GitHub | git/HTTPS | ✅ 直连 | 无 |

**关键结论**：所有通信都是**内网向外发起**或**公网对公网**，全程无需在公司防火墙上开任何入站端口。

## 八、架构的 5 大优势

1. **零内网穿透**：全程不需要在路由器上开任何端口，公司安全合规。
2. **断网保活**：你家电脑关机，训练照跑；Agent 断线重连，任务不丢。
3. **断点续训**：中间模型全留公司本地，崩溃了原地恢复，不用从云重新下载几 GB。
4. **极低成本**：云服务器 50元/月，OS S免了，硬盘40GB够用。
5. **GitOps 原生**：`git push` 即训练，天然版本管理，一次提交对应一次实验。
