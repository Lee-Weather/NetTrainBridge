# 实验笔记更新规范

## 一、实验编号规则

### 1.1 基础编号格式

实验编号由**文件名** + **实验序号**组成，格式为：

```
实验{N}_{实验次序号}
```

- **文件序号**：取自文件名中的数字。例如 `F1_mock {N}.md` → **{N}**
- **实验次序号**：从 **0** 开始，依次为 0, 1, 2, ...

**示例**：

| 文件名 | 第一个实验 | 第二个实验（大变化） |
| --- | --- | --- |
| `F1_mock {N}.md` | `# 实验 {N}_0` | `# 实验 {N}_2` |
| `F1_mock {M}.md` | `# 实验 {M}_0` | `# 实验 {M}_2` |

### 1.2 微调迭代编号（t 后缀）

当实验为**小范围参数调优**、**权重微调**、**尝试性修改**时，在次序号后加 `t` 后缀连续迭代：

```
实验{N}_{基次序号}t{迭代序号}
```

**判断标准**（满足任意一条即可使用 `t` 后缀）：

- 仅修改奖励权重（单项或少量几项）
- 仅修改超参数（如 `tracking_sigma`、`base_height_target`）
- 仅修改某单一函数实现（公式微调、阈值调整）
- 回滚/恢复某个之前的修改
- 训练结果未达到预期，需要小幅修正后重跑

**示例**：

| 实验 | 说明 |
| --- | --- |
| `# 实验 {N}_0` | 首个实验（基线） |
| `# 实验 {N}_0t1` | 基线基础上的第一次微调 |
| `# 实验 {N}_0t2` | 基线基础上的第二次微调 |
| `# 实验 {N}_0t3` | 基线基础上的第三次微调 |
| `# 实验 {N}_1` | 较大改动（不再属于基线微调，启动新实验） |

### 1.3 大变化实验编号（无 t 后缀）

当出现以下情况时，**不使用 `t` 后缀**，直接递增次序号：

- 新增或删除核心奖励函数
- 修改 URDF / 物理参数
- 修改参考轨迹生成逻辑
- 修改网络结构或观察空间
- 成功找到有效方案，进入下一阶段验证
- 单次修改中涉及 **≥3 个独立模块** 的联动变更

**示例**：

```markdown
# 实验 {N}_0      ← 首个基线实验
# 实验 {N}_0t1    ← 微调 reward weight
# 实验 {N}_0t2    ← 再次微调
# 实验 {N}_1      ← 新增 feet_contact 奖励（大变化，启动新实验）
# 实验 {N}_1t1    ← 微调 feet_contact 参数
# 实验 {N}_2      ← 修改 URDF（更大变化）
```

## 二、修改记录规则

### 2.1 连续微调（t 系列）：修改一、修改二连续记录

当实验属于 `t` 后缀的微调迭代时，**修改编号从"修改一"开始连续累加**，跨实验继承：

```markdown
# 实验 {N}_0

## 修改一：XXX
## 修改二：XXX

---

# 实验 {N}_0t1

## 修改三：YYY        ← 继承 {N}_0 的编号，继续累加
## 修改四：ZZZ

---

# 实验 {N}_0t2

## 修改五：AAA        ← 继承 {N}_0t1 的编号
```

**特点**：

- 所有 `t` 系列的修改共享同一个**连续编号序列**
- 编号使用中文数字：**修改一、修改二、修改三...**
- 便于追溯同一条修改线的演进历史

### 2.2 大变化实验（无 t 后缀）：重新从实验一开始

当实验属于**大变化**（无 `t` 后缀的新实验）时，**修改编号重新从"实验一"开始**，使用**中文"实验"**替代"修改"：

```markdown
# 实验 {N}_0

## 修改一：XXX
## 修改二：XXX

---

# 实验 {N}_1      ← 大变化，启动新实验

## 实验一：YYY    ← 重新从"实验一"开始
## 实验二：ZZZ

---

# 实验 {N}_1t1    ← 基于 {N}_1 的微调

## 实验三：AAA    ← 继承 {N}_1 的实验编号，继续累加
```

**判断对照表**：

| 场景 | 编号前缀 | 编号起点 | 是否跨实验继承 |
| --- | --- | --- | --- |
| `{N}_0`（首个基线） | 修改 | 修改一 | - |
| `{N}_0t1`（微调） | 修改 | 修改三（继承） | ✅ 继承 `{N}_0` |
| `{N}_1`（大变化） | 实验 | 实验一（重置） | ❌ 不继承 |
| `{N}_1t1`（微调） | 实验 | 实验三（继承） | ✅ 继承 `{N}_1` |
| `{N}_2`（更大变化） | 实验 | 实验一（重置） | ❌ 不继承 |

## 四、示例完整文档

```markdown
# 实验 {N}_0

## 上一实验结果与教训

> 本轮为首个实验，无上一实验。

## 本轮修改目标

建立基线，验证基础配置可行性。

## 修改内容

### 修改一：修复 last_feet_z 标量初始化

```python
# _init_buffers:
self.last_feet_z = torch.zeros(self.num_envs, 4, device=self.device)  # 标量→张量
```

**理由**：标量导致 feet_clearance 首步计算错误。

## 预期

| 奖励 | 预期值 |
| --- | --- |
| rew_feet_clearance | 0.3 |

---

# 实验 {N}_0t1

## 上一实验结果与教训

> {N}_0 训练后姿态正常，但 `rew_feet_clearance` 仅 0.1，低于预期 0.3。
>
> **教训**：`target_feet_height` 0.03 过低，不足以支持高速行走。

## 本轮修改目标

提升抬脚高度，验证 clearance 改善。

## 修改内容

### 修改二：提升 target_feet_height

| 参数 | 旧值 | 新值 |
| --- | --- | --- |
| target_feet_height | 0.03 | 0.05 |

## 预期

| 奖励 | 预期变化 |
| --- | --- |
| rew_feet_clearance | 0.1 → 0.3 |

---

# 实验 {N}_1

## 上一实验结果与教训

> 经过 {N}_0t1/t2 微调，`rew_feet_clearance` 达到 0.35，满足目标。
> 但发现新瓶颈：`rew_contact_symmetry` 仅 0.3，左右脚接触时间严重不对称。
>
> **教训**：仅靠抬腿高度无法解决接触对称，需要引入新奖励项。

## 本轮修改目标

新增 contact_symmetry 奖励，强制左右脚接触对称。

## 修改内容

### 实验一：新增 _reward_contact_symmetry

```python
def _reward_contact_symmetry(self):
    left_contact = self.contact_forces[:, self.feet_indices[0], 2] > 5.0
    right_contact = self.contact_forces[:, self.feet_indices[1], 2] > 5.0
    diff = torch.abs(left_contact.float() - right_contact.float())
    return 1.0 - diff
```

**奖励权重**：`contact_symmetry = 0.3`

### 实验二：降低 feet_clearance 权重

| 奖励 | 旧权重 | 新权重 | 理由 |
| --- | --- | --- | --- |
| feet_clearance | 2.0 | 1.0 | 给 contact_symmetry 让出梯度空间 |

## 预期

| 奖励 | 预期值 | 异常信号 |
| --- | --- | --- |
| rew_contact_symmetry | 0.75-0.9 | < 0.6 → 权重 0.3→0.5 |
```

## 六、注意事项

1. **编号一旦分配不可更改**：即使实验失败，也要保留原编号，不要删除或合并
2. **t 系列继承基于最近的非 t 实验**：{N}_1t1 继承 {N}_1，不继承 {N}_0t2
3. **"上一实验结果与教训" 必须具体**：不能只写"效果不好"，要给出具体数值和现象
4. **失败实验也要记录**：失败的实验同样有价值，标记为并写明失败原因
5. **大变化判断不清时，宁可不用 t**：不确定时用 {N}_1 而非 {N}_0t5，保证历史清晰
