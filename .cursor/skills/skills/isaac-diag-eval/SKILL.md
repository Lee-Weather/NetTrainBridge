# Isaac 诊断 CSV 改进评估

## 适用范围

输入一份 Isaac 仿真导出的逐 step 诊断日志 `czy/data/isaac_diag_*.csv`，判断**本轮训练相对上一轮是否改进**，并给出可写回实验笔记的结论。

与 `walk-diagnostics` 的分工：

| skill | 关注点 |
| --- | --- |
| `walk-diagnostics` | 对称性、跟踪误差、步态周期（稳态段统计） |
| **`isaac-diag-eval`（本 skill）** | **改进判定**：数据覆盖度、稳定性分窗、**高频抖动（FFT）**、**限位 bang-bang**、航向漂移 |

两者互补，分析新一轮 isaac_diag 时建议都跑，本 skill 负责"是否改进"的结论。

## 关键前提：先确认数据能验证什么

Isaac 诊断 CSV **新版已包含** base 线速度和接触力字段：
- `base_lin_vel_x/y/z`：机器人线速度（可验证速度跟踪）
- `left_foot_contact_force_z/mag`、`right_foot_contact_force_z/mag`：接触力（可验证落地冲击）
- `feet_contact_force_penalty`：接触力惩罚项（训练奖励值）

但**旧版本可能缺失**，且 `imu_accel_*` / `tau_des_*` 可能整列 NaN。因此：

| 实验目标 | 能否判定 |
| --- | --- |
| 稳定性 / 是否摔倒 | ✅ 能（base_euler + ang_vel） |
| 关节高频抖动（踝） | ✅ 能（vel / action FFT） |
| 限位 bang-bang 根因 | ✅ 能（pos_des_lpf/raw） |
| 航向漂移 | ✅ 能（base_euler_z） |
| 左右对称性 | ✅ 能（action 幅度） |
| **速度跟踪（如 1.5 m/s）** | ✅ **能**（有 base_lin_vel_x） |
| **落地冲击 / 接触力阈值** | ✅ **能**（有 left/right_foot_contact_force_z/mag） |

> ⚠️ 若CSV缺少线速度/接触力列，脚本会自动报告缺失项，此时速度跟踪/落地冲击目标需另取真机/MuJoCo日志。

## 分析脚本

脚本：`eval_isaac_diag.py`（与本文件同目录）。

```bash
# 默认：稳定性 1s 分窗，高频阈值 5Hz
python skills/isaac-diag-eval/eval_isaac_diag.py czy/data/isaac_diag_<时间戳>.csv

# 可调参数
python skills/isaac-diag-eval/eval_isaac_diag.py <csv> --win 1.0 --hf 5.0
```

脚本输出 9 个小节，依次对应下面的评估标准：

| 节 | 内容 | 主要列 |
| --- | --- | --- |
| 0 | 数据覆盖度（能/不能验证） | 全 NaN 列探测 + contact 是否恒 0 + 线速度/接触力列检查 |
| cmd | 命令速度/角速度 | `cmd_linear_x/y`, `cmd_angular_z` |
| 1 | 稳定性分窗 + 摔倒判定 | `base_euler_x/y/z`, `base_ang_vel_*` |
| 2 | 航向漂移 | `base_euler_z` vs `cmd_angular_z` |
| 3 | 关节高频抖动 | `vel_*`（FFT/过零）、`action_*`（d_action） |
| 4 | 限位 bang-bang | `pos_des_lpf_*` / `pos_des_raw_*` |
| 5 | 左右对称性 | `action_left/right_*` 活动幅度 |
| 6 | 关节力矩量级 | `effort_*` |
| 7 | **速度跟踪** | `base_lin_vel_x` vs `cmd_linear_x` |
| 8 | **落地冲击** | `left/right_foot_contact_force_z/mag` |

### 可配置项（脚本顶部常量）

- `HARD_LIMITS`：各关节硬/软限位下上限，用于 bang-bang 判定。默认取自 `exp_1.md` 实验 1_3（ankle_pitch `[-0.41, 0.35]`、ankle_roll `[-0.64, 0.64]`）。若限位调整，**同步改这里**。
- `LEG_JOINTS` / `ANKLE_JOINTS` / `SYM_BASES`：关节命名，与 CSV 列前缀一致。

## 评估标准

### 1. 稳定性（摔倒判定）
- ✅ `max|roll|` 且 `max|pitch|` < ~0.35 rad（20°），全程不超
- ⚠️ 偶发接近 0.35~0.6 rad
- ❌ 超 0.6 rad（~34°）→ 疑似摔倒/大幅失衡
- 分窗 `std|roll|`、`std|pitch|` 越小越稳；逐窗应平稳不发散

### 2. 航向漂移（直行 `cmd_angular_z≈0` 时）
- ✅ `|yaw 漂移|` < 0.15 rad（~9°）
- ⚠️ 0.15~0.4 rad
- ❌ > 0.4 rad（~23°）→ 明显跑偏，提示左右出力不对称

### 3. 关节高频抖动（踝关节为重点）
- ✅ 踝 `>5Hz 能量占比` < 0.5
- ⚠️ 0.5~0.7
- ❌ > 0.7 → 高频抖动严重
- 辅助：`vel 过零次数` 越高、`std(d_action)` 越大 = 抖动越重；与上一轮同关节对比看升降

### 4. 限位 bang-bang（抖动根因定位）
- ✅ 各关节 `pos_des` 顶限位时间 < 15%
- ⚠️ 15%~30%
- ❌ > 30% → 策略在限位边界 bang-bang，**这是踝抖动的常见根因**；单纯加阻尼/改随机化难治本，应从参考轨迹、default 角、限位匹配或动作平滑奖励入手

### 5. 左右对称性（action 活动幅度 L/R 比）
- ✅ 0.85~1.18
- ⚠️ 0.7~1.4
- ❌ 超出 → 系统性不对称（结合 URDF 右腿参数排查，见 exp_1.md 1_2t2）

### 6. 关节力矩
- 踝关节 effort 远小于髋/膝属正常；某关节 `max|tau|` 异常飙高 → 关注饱和/冲击

### 7. 速度跟踪（如 cmd_linear_x = 1.5 m/s）
- ✅ `base_lin_vel_x` 均值达到命令速度的 **90%+**（如 1.5→1.35+）
- ⚠️ 75%~90%
- ❌ < 75%（如 1.5→1.1）→ 速度跟踪不足，需增大 `tracking_lin_vel` 权重
- 同时检查 `base_lin_vel_x/y/z` 的 RMS 波动，波动过大说明控制不稳

### 8. 落地冲击（接触力阈值判定）
- ✅ 左脚峰值 < 150N（软着陆）
- ⚠️ 150~300N（中等冲击）
- ❌ > 300N（硬着陆）→ 需增大 `feet_contact_force_penalty` 权重
- 左右对比：峰值比应在 0.85~1.18（不对称会加剧单侧冲击）
- 交替着地模式：应有明显的左右交替（双支撑相占比合理）

## 改进判定逻辑（给 Agent）

1. **先跑脚本，读第 0 节**：确定本轮目标里哪些可验证、哪些不可验证，不可验证的明确说明并建议补日志。
2. **逐目标对照上一轮**：本 skill 关注的目标（稳定性/抖动）直接用脚本数值与上一轮 CSV 或笔记记录对比。
3. **改进 = 目标项变好且无新退化**：
   - 若目标项（如踝抖动）**无改善或变差** → 本轮**不算改进**，即使没摔。
   - 若出现新问题（如航向漂移、对称性恶化）→ 标注为新退化。
4. **根因优先于现象**：发现 bang-bang 占比高时，提示"抖动根因在限位边界，调阻尼难治本"，引导下一轮方案。
5. **结论措辞要分级**：✅改进 / ⚠️部分改进（某项好某项平/差）/ ❌未改进。不要笼统说"好/不好"。

## 分析报告模板

```markdown
## Isaac 诊断分析报告：实验 <编号>

> 数据：`isaac_diag_<时间戳>.csv`（Isaac 仿真，<时长>s，<采样>Hz，cmd=<速度> m/s）
> 本轮目标：<目标1> / <目标2> / ...

### 0. 数据可验证性
- ✅ 可验证：稳定性、抖动、航向、对称性、力矩
- ❌ 不可验证：<速度跟踪/接触力 等> —— 需 <真机/MuJoCo> 日志

### 逐目标结论
| 目标 | 判定 | 依据（关键数值） |
| --- | --- | --- |
| <稳定性> | ✅/⚠️/❌ | max|roll|=…, 分窗 std=… |
| <踝抖动> | ✅/⚠️/❌ | 踝 HF占比=…, vel过零=…, bang-bang=…% |
| <速度/冲击> | 无法判定 | 此 CSV 无对应字段 |

### 附带发现
- 航向漂移 <…> deg；对称性 knee_pitch L/R=<…>；…

### 总体判断
✅改进 / ⚠️部分改进 / ❌未改进 —— 一句话理由

### 下一轮建议
1. …（针对根因，而非现象）
```

## 注意事项

1. **不臆测缺失数据**：速度/接触力没记录就直说，不要用关节量"推算"速度当结论。
2. **HARD_LIMITS 要与当前 URDF/推理 clip 一致**，否则 bang-bang 判定失真。
3. **窗口/阈值可调**：短日志（<5s）可减小 `--win`；只看更高频抖动可增大 `--hf`。
4. **结论写回笔记**：按 `skills/lab-notebook` 规范填入对应实验的"实验结果"。
5. **临时脚本即用即删**：一次性探查可临时建脚本，分析完清理；可复用逻辑沉淀进 `eval_isaac_diag.py`。
